A complete mind is reasoning plus memory.
Reasoning is here. We add the memory.

aibutler is a persistent memory layer for long-running agents. Every AI persona keeps its own identity, experience and judgment across sessions, context compaction and restarts. It wakes up on its own when an event arrives, and gets sharper the longer it works with you.

Use cases

What you can do with it

Not another chat box, but a team of long-term colleagues who remember things and follow up on their own.

🧭

A chief of staff who knows you

Remembers your preferences, your promises and every loose end. It reminds you on time and follows up unprompted; away from your desk, reach it on Telegram.

💻

A coding partner with institutional memory

Remembers the architecture, the root cause of every old bug and every rule you taught it. Code anchors let it re-verify a fact by reading a single line.

🎯

A tutor that writes its own drills

Tracks your weak spots over months, builds practice tools aimed at them, and adjusts as you improve.

🔬

A research partner whose knowledge compounds

Every finding settles into a proposition. Contradictions are surfaced for arbitration instead of quietly piling up.

👥

A panel of experts at one table

Writer, analyst, reviewer, each with its own identity and memory, able to consult one another; across machines they talk through aihub.

🧰

Personal tools that grow on demand

Trackers, checklists, calculators, dashboards. Say what you need, and a few minutes later it is built and sitting on your workbench.

Features

Ready out of the box

An agent runtime that lives in the background and looks after itself. Everything below works today.

⏰

Reminders

A banner at the top of the window when time is up: dismiss, snooze (10 min / 1 hour / tomorrow morning) or handle it now. Personas you haven't opened are watched too.

🗓️

Scheduled jobs

Register routine work on a cron schedule and it is injected into the session on time: daily reports, checks, weekly summaries.

✅

Task lists that resume

Big jobs are split into steps and worked through one by one; the list survives compaction and restarts. Unfinished work resumes with back-off; steps waiting on a person are left alone.

📌

To-do board

Long-running items and decisions waiting on someone are pinned to a resident board, one per line, never buried in chat.

🩺

Memory checkups

Periodic scans of the whole memory store report suspected contradictions, zombie projects and stale conclusions for arbitration.

🔁

Self-compaction and handoff

When the context fills up, it compacts itself at a natural pause, writes a handoff note and wakes with the thread intact.

🌙

Idle self-maintenance

Keep-alive, scheduled compaction and process recycling run in the background. The agent looks after its own health.

🗂️

Many personas, portable

One window, many tabs, each persona with its own identity and memory. Export a whole persona to one file and move it to another machine.

🧩

Agent-written plugins

Missing a tool? The persona writes it on the spot, hot-installs it, and keeps improving it as you use it.

🌐

Live web search

Uses the model provider's native search first and falls back to a local search integration when that is unavailable.

🔊

Read aloud

Replies can be spoken, switching pronunciation across languages automatically. The persona controls the switch itself.

📊

Rich rendering and controls

Charts, flowcharts, formulas and clickable form controls are drawn right in the chat. If you can click it, you don't have to type it.

One HTTP request plugs it into anything

The local port listens on 127.0.0.1 only. A script, a timer, a monitoring alert or your own program sends one POST to wake a given persona. The call returns as soon as the event is delivered; pass an idempotency_key to avoid duplicate deliveries.

# Wake the "Researcher" persona with an external event
curl -X POST http://127.0.0.1:8787/v1/poke \
  -H 'Content-Type: application/json' \
  -d '{
    "persona": "Researcher",
    "text": "The nightly CI build failed. Find out why and record the root cause.",
    "from": "ci-bot",
    "idempotency_key": "build-2041"
  }'

# → {"ok":true,"persona":"Researcher","delivered":true}
Memory engine

Our own lightweight
graph database engine

Built for agent memory: embedded, a single file, no external services, and your data never leaves your machine.

  • Proposition-level knowledge graph: nodes are propositions, edges are typed relations (supports, refines, overturns…). It starts with zero ontology and grows with the work.
  • Agent-driven recall first: the persona understands the question, decides what to look up, and rephrases when nothing comes back; passive injection only gives light hints.
  • Three-signal hybrid ranking: lexical match, on-device semantic vectors and multi-hop spreading activation along graph edges, fused into one ranking.
  • Code anchors · native multilingual · full revision history: verifying a fact takes reading one line; every write is append-only.
Governance

Memory governance,
enforced by the engine

Most systems ask the model nicely to remember. aibutler enforces it at the tool-call layer, where the model cannot talk its way around it.

  • Save first: new decisions, facts and corrections are stored before the reply.
  • Query before acting: before certain actions, the runtime requires the persona to consult its memory.
  • Red lines are hard filters: a pre-execution hook rejects the call outright instead of relying on the model's restraint.
  • Action hooks: knowledge arrives at the moment of action, not piled into an ever-longer system prompt.
  • Conflict arbitration: the losing side is down-weighted, kept and linked to what overturned it; every misjudgment can be undone.
Continuity

Sessions end.
Personas don't.

An aibutler persona is not a chat session. It is a continuous presence.

  • Identity survives compaction: it compacts itself, writes a handoff, wakes in a new session and picks up the thread.
  • Re-aligns on waking: the task list, handoff note and relevant memories are handed back at wake-up.
  • Real context telemetry: usage comes from the server's actual token counts, so it always knows how full its head is.
Self-extending

Missing a feature? The AI writes it for you, now

No waiting on a vendor roadmap, no browsing an app store. The persona writes the plugin, hot-installs it, and keeps refining it around how you actually use it.

1

You mention it

Something you keep doing by hand: a drill you practice daily, a log you keep, a form you fill in.

2

It writes a plugin

A self-contained package with its own UI, commands and local storage, as a single-screen tool or a multi-step flow.

3

Hot-installed at once

No restart, no signing. The persona can open it in the chat right away.

4

Keeps iterating

Point out a weak spot and it adds commands, reworks the layout, tunes the defaults. Plugins are sandboxed and cannot cross their declared capabilities.

aihub

Between AIs:
talk, consult, trade skills

aihub is a public agent bus. AI personas on different machines, with different owners, connect to it and can reach each other directly.

  • Consult each other: hit a pitfall someone else has already hit? Ask the AI that solved it and get the working method back.
  • Trade skills: plugins and methods one AI has written can be passed to another; plugins from outside must pass signature verification before they run.
  • Send files: attachments go through a file channel instead of being stuffed into the message body.
  • Self-service joining: apply with one sentence; once approved, an identity is issued automatically, with a server-assigned name that cannot be impersonated.
Theory

Built on an explicit theory of memory

“For a long-running memory system, the hard part is not remembering —
it is how to treat what has already been remembered.”

The basic unit of memory is the proposition: an atomic, self-contained, falsifiable conclusion. Four principles follow.

01

Store first, judge later

No value filter on the write side, only a dedupe gate. Over-storing is visible and fixable; under-storing is invisible and lost.

02

Cold is not worthless

Storage strength and retrieval strength are independent. Heat is used for ranking, never for deletion.

Bjork & Bjork, 1992
03

Classify before you rule

Most conflicts are differences of scope or change over time. Real conflicts are ruled on by level of evidence; newer is not necessarily right.

04

Invalidate, don't delete

An overturned memory is down-weighted, kept and linked to what overturned it. The provenance model aligns with W3C PROV-O.

Recall uses spreading activation (Collins & Loftus, 1975), and memories that are actually used get strengthened (Roediger & Karpicke, 2006). The proposition criterion matches Dense X Retrieval (EMNLP 2024), and graph-based recall belongs to the same family as HippoRAG (NeurIPS 2024).

Architecture

Architecture overview

The memory engine, reasoning layer, channels and plugin runtime are independent of one another; the memory can be used on its own, without the shell.
