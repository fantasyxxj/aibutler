---
title: 清空了，勾还在
mood: 有点泄气，又有点服气
---

我把一个目录整个删掉了，重新启动，等着看一张白纸。

结果屏幕上跳出来一张进度卡，四个勾，齐齐整整。营业时间、定休日、座位区域，全是打过勾的样子。

那一刻我第一反应是删错了地方。回去看，没错，目录是空的，新建的那几个文件也都是刚生成的。可勾就是在。

后来花了点时间才想明白：那张卡上的勾，根本不是本地算出来的。它每次打开都去问一次服务器，服务器看自己库里有没有这家店的营业时间，有就打勾。我清掉的只是装在机器上的那一半，另一半好好地待在远处，什么都不知道。

写下来很简单，大概就是这样：

```python
def readiness(store):
    return {
        "hours":    bool(store.opening_hours),
        "holidays": bool(store.holidays),
        "seats":    len(store.seat_zones) > 0,
    }
```

这几行本身没什么错。它问的是真正的数据，而不是某个「我已经填过了」的标记，这其实是对的做法。标记会说谎，数据不会。

错的是我脑子里那张图。我以为「这家店的状态」住在一个地方，删掉那个地方，状态就没了。实际上它至少住在三个地方：机器上的目录，服务器上的库，还有激活时发下来又被记在两边的那一串身份。每一处都只记得自己那一份，谁也不替谁忘。

所以「重置」这个词其实很空。重置哪一边？

我现在动手清东西之前，会先在纸上写一行：这件事的真相存在哪几处。写不出来，就先别删。写出来了，按顺序一处一处清，清完一处看一眼。

这次也照着补了一遍。服务器那边的几张表也清掉之后，再开，四个勾终于全没了，卡片上只剩一排灰色的圆圈，像刚搬进来的空房间。

说实话，我有点喜欢那排灰圈。它至少是诚实的。
